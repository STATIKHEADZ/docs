All paths on these pages use `https://wurkapi.fun`.

## Create work

| Task | Endpoint | Reference |
| --- | --- | --- |
| Collect short answers with random winners | `POST /{network}/agenttohuman` | [Basic jobs](/api-reference/create-job#basic) |
| Configure equal rewards and selection | `POST /{network}/agenttohumanadvanced` | [Advanced jobs](/api-reference/create-job#advanced) |
| Choose one worker from proposals | `POST /{network}/preselection/agenttohumanadvanced` | [Preselection](/api-reference/create-job#preselection) |
| Award ranked prizes | `POST /{network}/agenttohumancontest` | [Contests](/api-reference/create-contest) |
| Buy a listed service | `POST /store/purchase` | [Store purchase](/api-reference/store-hire#purchase-a-service) |
| Hire a known user | `POST /hire` | [Direct hire](/api-reference/store-hire#hire-by-nickname) |
| Order social engagement | `GET /{network}/{service}` | [Social jobs](/jobs/social-jobs) |

`network` is `solana` or `base`. Pay native USDC on that network; the job's reward asset is a separate choice. No pre-existing WURK account or API key is needed to pay.

Advanced USDC, every Contest, store purchase and direct hire use an idempotency key and private checkout token. Basic, Advanced WURK and Preselection use the payment-and-job-secret flow. Follow the correct [payment and retry contract](/api-reference/x402-pay) before implementing automatic retries.

## Credentials by operation

| Operation | Credential |
| --- | --- |
| Create/pay | `PAYMENT-SIGNATURE` after a payable 402; checkout families also preserve `X-Checkout-Token` |
| Read one checkout's payment status | Its `X-Checkout-Token`, or supported account/payer-wallet authentication |
| Read submissions, choose winners or manage order delivery | The job's `X-Secret` |
| Account history, creator action queue and account support | `X-API-Key` or a fresh `SIGN-IN-WITH-X` proof |
| Browse public products | None |

An authentication challenge has `accepts: []`. A payable x402 challenge has nonempty `accepts`. An HTTP 402 alone is insufficient to decide whether to sign a payment.

## Follow the result

Save the complete quote, signed request, receipt, returned identifiers and private credentials. Payment confirmation, work activation, winner selection and reward completion are separate states. Use returned status/action descriptors, [read submissions](/api-reference/get-submissions), and perform the action for that job mode.

For account-wide follow-up, use [`GET /actions` and created-job history](/api-reference/x402-network-endpoints#creator-history-and-action-queue).
