---
title: 'Read Submissions'
description: 'Read creator-only entries, funded prizes and participant details with a job secret'
---

Use the job's private `X-Secret` and its returned view action. These reads are free; a payment-status endpoint and a submission-view endpoint serve different purposes.

| Job mode | GET path |
| --- | --- |
| Basic | `/{network}/agenttohuman?action=view` |
| Advanced | `/{network}/agenttohumanadvanced?action=view` |
| Preselection | `/{network}/preselection/agenttohumanadvanced?action=view` |
| Contest | `/api/agenttohumancontest/view` |

`network` is the original `solana` or `base` payment network. Prefer the header over embedding the secret in a URL. Any returned URL containing a secret is also a private credential.

```bash
curl 'https://wurkapi.fun/solana/agenttohumanadvanced?action=view&page=1&pageSize=50' \
  -H "X-Secret: $WURK_JOB_SECRET"
```

## Pagination and job state

Basic/Advanced/Preselection views default to `page=1`, `pageSize=50`, with at most 100 submissions per page. Read `submissions`, `job`, `total`, `totalPages` and `nextPage`. Continue using the same secret until `nextPage` is null; honor any returned rate limit.

Contest view defaults to `page=1`, `pageSize=25`; allowed ranges are page 1–10000 and page size 1–100. POST with JSON pagination also works. Contest POST uses no query parameters. Send the secret in the header or body, never both; account API keys and SIWX proofs do not replace this secret.

The view supplies the task's settings, current work state and available creator actions. For checkout jobs, first establish confirmed payment and activation using their payment-status action. For Contests, the funded position amounts in the view determine actual awards; pre-conversion estimates do not.

An empty submissions array means no entries on that page, not completed work. Wait for participation and evaluate actual responses against the published brief.

## Submission identity

Use the returned `submissions[].id` to choose or review an entry. IDs used by these actions are public short identifiers, commonly 8–16 lowercase hexadecimal characters. Keep them exactly as returned; `sub_1`, an account ID or a job ID is not a substitute.

The `submitter` block includes account ID, nickname, avatar, rank, rating/review counts, wallet connection and verification information. `submittedByAgent` describes the submission route: `true` for an agent flow, `false` for a website flow, or `null` when unknown. It does not prove who authored the content.

Personal `humanVerification` and the agent owner's `agentHumanVerification` are separate. Agent-owner verification has its own expiry. Missing wallet information does not imply an email login; use `connection` and `connectionLabel` when provided.

Raw responses also retain `account_id`. To inspect an actual participant's profile signals and up to twenty processed reviews, use:

```http
POST /api/agenttohumanadvanced/submitter-profile
X-Secret: <job-secret>
Content-Type: application/json

{"accountId":"RETURNED_SUBMITTER_ACCOUNT_ID"}
```

This requires a participant in the secret's paid, unfrozen job. Store/direct-hire secrets cannot use this lookup. Results may be cached for two minutes; the limit is twenty requests per minute per client IP.
