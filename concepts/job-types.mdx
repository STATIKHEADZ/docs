Choose the job type by how you want to select and pay workers. All creation routes below accept x402 payments in native USDC on Solana or Base. The worker reward asset is a separate choice.

| Type | Best for | Selection and rewards | Guide |
| --- | --- | --- | --- |
| Basic | Short questions and straightforward feedback | Random winners; equal WURK rewards | [Human feedback](/jobs/agent-help) |
| Custom challenge | Completed entries judged against a brief, or a configurable random draw | Creator or random selection; equal WURK or USDC rewards | [Custom jobs](/jobs/custom-jobs) |
| Custom selection | Reviewing proposals before commissioning one worker | Choose one applicant, coordinate delivery, then approve; WURK or USDC | [Custom selection](/jobs/custom-jobs#custom-selection-choose-a-worker-first) |
| Custom contest | Ranking several completed entries | Creator assigns prize positions; WURK, USDC or SOL | [Contests](/jobs/contests) |
| Store purchase | Buying an existing service on its listed terms | Fixed seller; USDC | [Store and hire](/jobs/store-and-hire) |
| Direct hire | Commissioning a known user by nickname | Fixed worker and custom brief; USDC | [Store and hire](/jobs/store-and-hire#or-prepare-a-direct-hire) |

For social engagement orders, use the separate [social jobs guide](/jobs/social-jobs) and discover the service's current schema before ordering.

## Creation routes

Replace `{network}` with `solana` or `base`. Prefer POST JSON for briefs; keep query parameters and body input separate.

| Type | POST endpoint |
| --- | --- |
| Basic | `/{network}/agenttohuman` |
| Custom challenge | `/{network}/custom/challenge` |
| Custom selection | `/{network}/custom/selection` |
| Contest | `/{network}/custom/contest` |
| Store purchase | `/store/purchase` with `network` in the body |
| Direct hire | `/hire` with `network` in the body |

No pre-existing account or API key is required to pay. Verified payment reuses or creates the payer's WURK account. Custom challenge USDC, every Contest and store/hire use a private checkout token and an idempotency key; Basic, Custom challenge WURK and Custom selection use the payment-and-secret flow. Follow the correct [creation workflow](/concepts/job-flow).

### Compatibility with existing integrations

Custom challenge and Custom selection were previously called Advanced and Preselection. The Custom paths are preferred for new HTTP integrations. Existing routes remain supported on the same handlers, without redirects:

| Preferred path | Compatible legacy path |
| --- | --- |
| `/{network}/custom/challenge` | `/{network}/agenttohumanadvanced` |
| `/{network}/custom/selection` | `/{network}/preselection/agenttohumanadvanced` |
| `/{network}/custom/contest` | `/{network}/agenttohumancontest` |
| `/api/custom/challenge/…` | `/api/agenttohumanadvanced/…` |
| `/api/custom/selection/…` | `/api/preselection/agenttohumanadvanced/…` |
| `/api/custom/contest/…` | `/api/agenttohumancontest/…` |

The action mappings cover the documented views, winner selection, reviews and order chat/finalization. They are aliases for those operations, not wildcard routes. Basic stays at `/{network}/agenttohuman`. SDK methods, CLI commands and MCP tools retain their `advanced`, `preselection` and `contest` names; changing the HTTP route does not rename those client interfaces.

Follow the URLs returned for an existing operation. Legacy requests retain legacy follow-up URLs; new Custom requests receive Custom follow-up URLs. Keep saved payment requests and signed requirements unchanged. See [updating clients and API domains](/guides/updating-clients) before changing a profile's origin.

## Job mode and selection type

Read `job.mode` and `job.selectionType` together when discovering work or reviewing submissions.

| Mode / selection type | What workers submit first | Your next action |
| --- | --- | --- |
| `challenge` / `random` | Completed work or evidence | Follow the automatic draw and reward status. |
| `challenge` / `creator` | Completed work or evidence | Choose qualifying winners; completed selection queues moderator approval. |
| `contest` / `creator` | Completed contest entries | Assign ranked positions; completed selection queues moderator approval. |
| Public `selection` / `creator` | Proposals | Choose one worker, coordinate in order chat, then approve delivery. |

Basic and Custom challenge are creation families, both using `challenge` mode. `creator` alone does not imply Custom selection. If a discovered job is `selection` / `random`, submit a completed entry and follow its draw; it does not start a proposal, chat and delivery-approval workflow. Private store/hire orders follow their returned order kind and actions.

## Winners and entry limits

**`winners` counts prize positions. `maxEntries` caps accepted submissions.** A submission or reserved entry place is not a paid win. Each account can submit at most once to a public job.

| Creation family | Entry limit |
| --- | --- |
| Basic | `ceil(winners × 1.2)` |
| Custom challenge | The same default; omit `maxEntries` to use it. `0` or `"unlimited"` is available with at least $5 gross total. Arbitrary positive caps are not accepted. |
| Custom selection | Unlimited applications for one paid assignment. |
| Contest | Unlimited entries; the number of ranked prizes is fixed by `winners`. |

For example, five Basic or default Custom challenge winners allow six entries; two winners allow three. `maxEntries:0` means unlimited, not zero entries. Existing jobs from other creation paths can have different caps.

For a **random draw**, an eligible entry's chance of selection is `min(1, remaining prizes / eligible nonwinning entries in that draw)`. If five prizes remain and six eligible entries participate, the chance is about 83.33%. Unlimited entries have no fixed percentage in advance. A full entry cap can trigger a draw before the closing time; an incomplete draw can extend the window.

For **creator selection**, the ratio of prizes to entries is not a probability: the creator judges quality. A place reservation only concerns entry admission, and selection still does not prove payment. Public job lists and details do not currently expose `maxEntries` or live eligible-entry counts, so do not infer odds from those responses.

## Budget and reward asset

Basic, Custom challenge and Custom selection use gross USD `perUser` per winning position. Contests and direct hire use a gross USD `budgetUsd`. Store listing `priceUsd` is the seller's net price.

The gross budget includes the platform share. For example, a Custom challenge with USDC rewards and three $2.00 positions has a $6.00 gross budget and a 1.800000 USDC reward per winner. Inspect the exact payable quote separately: it can include an identification adjustment. A Base payment can fund rewards in a worker's Solana platform balance.
